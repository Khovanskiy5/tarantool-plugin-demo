# Сценарий демонстрации tarantool-idea-plugin

Проект подготовлен так, что каждая возможность плагина срабатывает
на готовых файлах. Порты кластера — **3311/3312/3315** (3301 занят
инстансом из `tarantool-learn`). Учётная запись — `client` / `secret`.

Что понадобится: IntelliJ IDEA 2026.1+ с установленным плагином;
для раздела «Данные» — Ultimate; для гуттер-иконок, автодополнения
и Emmy-отладки — плагин EmmyLua2.

## 1. Автоматика при открытии проекта

Откройте каталог `tarantool-plugin-demo` как проект. Сразу видно три
вещи:

* уведомление **«Сгенерировать типы Tarantool?»** — потому что в корне
  есть `tt.yaml`, а каталога `.types/tarantool` ещё нет;
* в IDEA Ultimate — уведомление о созданных **источниках данных**:
  плагин прочитал `config.yaml` и завёл `tarantool-plugin-demo-router-001-a@3315`
  и `tarantool-plugin-demo-storage-001-a@3311` (лидер). RO-реплика
  `storage-001-b@3312` сознательно пропущена;
* готовые конфигурации запуска в выпадающем списке Run — они лежат
  в `.run/` и подхватываются автоматически.

## 2. Схемы конфигурации YAML

Откройте `config.yaml`: в статус-баре — схема **Tarantool cluster
config** (официальная JSON Schema Tarantool 3). Нажмите Ctrl+Space
внутри секции `iproto:` или наберите новую опцию верхнего уровня —
автодополнение с документацией; опечатка в имени опции подсвечивается.
Схема активна потому, что рядом лежит `instances.yml` (второй триггер —
`tt.yaml` в корне).

Откройте `tt.yaml` — схема **tt environment config** (разделы `env`,
`app`, `modules`, `repo`, `ee`, `templates`).

## 3. Панель «Tarantool»

Внизу IDE — вкладка Tarantool: таблица трёх инстансов (`tt status`):
состояние, PID, режим RW/RO, готовность config и box; автообновление
каждые 5 секунд.

1. Нажмите **Запустить** — `tt start` поднимет кластер.
2. Убедитесь: `router-001-a` и `storage-001-a` в RW, `storage-001-b` в RO.
3. Кнопка **Логи** — хвост журнала (`tt log -f`) в Run-консоли. Строки
   вида `schema.lua:27 I> спейс users создан…` кликабельны — имя файла
   без каталога разрешается поиском по индексу проекта.
4. Кнопка **Консоль** — вкладка встроенного Терминала с `tt connect`
   к выбранному инстансу. Попробуйте:

   ```
   box.space.users:select()
   \set language sql
   SELECT * FROM SEQSCAN "users";
   ```

Кластер оставьте запущенным — он нужен для разделов 10–11 и 13.

## 4. Конфигурация «Tarantool» + LUA_PATH

Запустите **«Tarantool: hello.lua»**. Скрипт делает
`require('model.users')` — модуль лежит в `src/model/users.lua`
и находится потому, что флажок LUA_PATH добавил корень проекта и `src/`
в пути поиска. В выводе — кириллица, `_TARANTOOL`, аргументы
из конфигурации (`--from-run-config`).

Откройте Run → Edit Configurations → «Tarantool: hello.lua»: поля
скрипта/интерпретатора/аргументов/рабочего каталога, макросы
`$PROJECT_DIR$`, редактор переменных окружения, флажки LUA_PATH
и отладчика.

## 5. Кликабельные трейсбеки

Запустите **«Tarantool: кликабельный трейсбек»**. Скрипт падает; в
консоли ссылка `./src/model/users.lua:31` — клик открывает строку
с `error(...)`. Выше — строка журнала до падения: формат
`имя_файла:строка` тоже кликабелен.

## 6. Встроенный отладчик (tarantool -d)

Запустите **«Tarantool: встроенный отладчик (-d)»**. Скрипт стартует
под интерактивной консолью luadebug прямо в окне Run (флажок
конфигурации «Запустить со встроенным отладчиком»):

```
help            -- список команд
b debugger_demo.lua:12
c               -- continue до точки останова
p weight        -- печать переменной
n               -- шаг
c               -- до конца
```

Кнопка Debug у конфигураций «Tarantool» отключена сознательно — свой
протокол отладки плагин не реализует (для графической отладки — раздел 10).

## 7. Контекстный запуск и гуттер ▶

Правый клик по `scripts/hello.lua` в дереве проекта или редакторе →
**Run** — конфигурация создаётся автоматически. С установленным
EmmyLua2 в первой строке файла появляется гуттер-иконка ▶.
Файлы `*_test.lua` перехватывает раннер luatest (раздел 9), а не
обычный запуск — попробуйте правый клик по `test/users_test.lua`.

## 8. Конфигурация «tt (Tarantool CLI)»

В списке Run — папка tt: `tt start`, `tt stop -y`, `tt status`,
`tt log -f`, `tt check app.lua`. Любая команда tt выполняется в окне Run
с псевдотерминалом. В Edit Configurations поле «Команда» подсказывает
варианты, включая `log -f tarantool-plugin-demo:storage-001-a` —
имена инстансов берутся из `instances.yml`.

## 9. Раннер luatest

Запустите **«luatest: все тесты»** (или правый клик по
`test/users_test.lua` → Run). Дерево результатов строится из TAP-вывода:
группа `users`, 5 зелёных тестов. Сломайте любой assert — тест станет
красным с диагностикой.

Раннер запускает `.rocks/bin/luatest -o tap -v` — luatest уже
установлен в проект (`tt rocks install luatest`).

## 10. Emmy-отладчик (графический, нужен EmmyLua2)

Как это устроено: слушает не IDE, а сам процесс Tarantool — при старте
он открывает порт отладчика 9966 (нативная библиотека emmy_core из
плагина EmmyLua2, её подгружает `emmy_debug.lua`). Конфигурация
**«Tarantool: attach debugger»** — клиентская сторона: кнопка Debug
подключает IDE к уже слушающему процессу. Отсюда порядок шагов:
запустить инстанс с отладчиком → подключиться → выполнить код с точкой
останова. Точки срабатывают только в коде, выполняющемся после
подключения IDE, — стартовый код (`schema.bootstrap`) к этому моменту
уже отработал, поэтому демонстрация идёт на функции, которую мы
вызовем из консоли сами.

1. **Разовая настройка: Tools → Настроить Emmy-отладчик Tarantool.**
   Плагин положит `emmy_debug.lua` в корень (рядом с `config.yaml`)
   и создаст конфигурацию «Tarantool: attach debugger». Вызов
   `require('emmy_debug').attach_if_requested()` уже стоит в начале
   `src/app.lua`; без переменной окружения `TARANTOOL_DEBUG` он не
   делает ничего, так что обычные запуски кластера не меняются.

2. **Запустите кластер с отладчиком.** Остановите кластер (панель или
   `tt stop -y`) и запустите из терминала — переменную окружения
   передаёт только ручной запуск:

   ```sh
   TARANTOOL_DEBUG=storage-001-a tt start
   ```

   Значение — имя инстанса из `instances.yml`, который откроет порт.
   В кластере имя обязательно: все три инстанса выполняют один и тот же
   `app.lua`, и при `TARANTOOL_DEBUG=1` они боролись бы за порт 9966
   (порт меняется переменной `EMMY_PORT`).

   Проверка: в журнале инстанса появилась строка «отладчик слушает
   порт 9966, подключайтесь из IDE» —
   `tt log tarantool-plugin-demo:storage-001-a`; либо
   `lsof -iTCP:9966 -sTCP:LISTEN` показывает процесс tarantool.

3. **Поставьте точку останова** в `src/model/users.lua` на строке 9 —
   это первая строка тела `users.validate`
   (`if type(user) ~= 'table' then`): клик по полю слева от номера
   строки, появится красный кружок.

4. **Подключите IDE:** кнопка **Debug** у «Tarantool: attach debugger».
   Проверка: открылось окно Debug, и в нём нет ошибки соединения
   (connection refused означает, что шаг 2 не выполнен).

5. **Спровоцируйте выполнение.** В консоли инстанса `storage-001-a`
   (панель Tarantool, либо
   `tt connect tarantool-plugin-demo:storage-001-a`):

   ```lua
   require('model.users').validate({ id = 4, name = 'Тест', email = 'test@example.com' })
   ```

   Проверка: консоль не получает ответ («висит»), а в окне Debug
   подсвечена строка `users.lua:9`, во Variables видна таблица `user`
   с полями. **Step Over** проходит проверки по одной, **Resume**
   отпускает выполнение — консоль сразу печатает результат.

## 11. Данные через Database Tools (Ultimate)

Кластер должен работать (раздел 3). В окне **Database**:

* два источника, созданные автоматически, с драйвером
  **Tarantool (shim)** и SQL-диалектом Tarantool;
* откройте `tarantool-plugin-demo-storage-001-a@3311` → таблицы `users`
  и `orders` (видны потому, что у спейсов задан `format`);
* двойной клик по `users` — грид с данными (кириллица, пагинация);
  `orders` открывается вместе с колонкой `created_at` типа `datetime` —
  ext-типы MsgPack (datetime, uuid, decimal, interval) декодирует
  форк `MsgPackLite` внутри shim-драйвера.
  Полный скан уже разрешён: в `config.yaml` включено
  `compat: sql_seq_scan_default: 'old'`;
* отредактируйте ячейку и нажмите Submit — запись проходит благодаря
  эмуляции автокоммита в драйвере-обёртке (каждая операция применяется
  сервером сразу; rollback честно предупреждает, что откат невозможен);
* откройте `playground/queries.sql` в SQL-консоли источника: `SEQSCAN`,
  `SET SESSION "sql_seq_scan"`, типы `UNSIGNED/STRING/UUID/DATETIME/MAP`,
  `LIMIT/OFFSET`, `AUTOINCREMENT` — ложных ошибок подсветки нет;
* в источнике роутера `@3315` таблиц нет — данные живут в хранилище.

Диалект назначается и вручную: Settings → Languages & Frameworks →
SQL Dialects → «Tarantool».

## 12. Генерация типов для EmmyLua2

Согласитесь на предложение из раздела 1 (или **Tools → Сгенерировать
типы Tarantool**). Появятся `.types/tarantool/generated/` (интроспекция
установленного Tarantool 3.8), `.types/tarantool/manual/` (уточнённые
сигнатуры `box`, `fiber`, `net.box` — ваши правки не перезаписываются)
и `.emmyrc.json`. После индексации в любом `.lua`:
`box.space.` → автодополнение, `fiber.` → сигнатуры с документацией.

## 13. Просмотр .snap / .xlog

Кластер уже создавал снапшоты: откройте
`var/lib/storage-001-a/00000000000000000032.snap` двойным кликом —
YAML-расшифровка через `tt cat` в редакторе только для чтения
(видны INSERT спейса `users` с демо-данными). Рядом — `.xlog`.
Вывод длиннее 20 000 строк обрезается с пометкой.

## 14. Проверка синтаксиса (tt check)

Правый клик по любому `.lua` (редактор или дерево проекта) →
**Проверить синтаксис (tt check)** — уведомление «syntax is OK».
Внесите синтаксическую ошибку — уведомление покажет строку из stderr.

## 15. Live-шаблоны

Откройте `playground/live_templates.lua`, наберите `tspace` и Tab —
развернётся создание спейса с format и первичным индексом. Остальные:
`tonce`, `tfiber`, `tatomic`, `tnetbox`, `tlog`, `twatch`. Работают
в любом `.lua`-файле даже без EmmyLua2. Список: Settings → Editor →
Live Templates → Tarantool.

## 16. Мастер нового проекта

**File → New → Project… → Generators → Tarantool** — имя, каталог
и шаблон: `single_instance`, `cluster`, `vshard_cluster`,
`config_storage`. Плагин выполнит `tt init` и `tt create
--non-interactive` (для vshard — ещё `tt build`) и создаст `.gitignore`.
Демо-проект открыт отдельно, поэтому мастер удобно показать, создав
одноразовый проект, например, из шаблона `vshard_cluster`.

## 17. Режимы запуска: локально, Docker, Kubernetes

**Settings → Tools → Tarantool → Режим запуска** (хранится
в `.idea/tarantool.xml`):

* **Локально** — всё, что показано выше;
* **Docker** — префикс `docker compose exec tarantool`: панель, логи
  и консоль выполняют tt внутри контейнера. Заготовка —
  `docker-compose.yml` (проброшены порты 3311/3312/3315, том с проектом);
* **Kubernetes** — namespace + селектор подов: панель показывает поды
  (`kubectl get pods`), перезапуск — `kubectl delete pod` (пересоздаёт
  контроллер), логи — `kubectl logs -f`, консоль — `kubectl exec -it`.

Там же, в **Settings → Tools → Tarantool**, — пути к `tarantool` и `tt`,
если IDE не видит PATH шелла.

## Завершение

Остановить кластер: панель Tarantool → **Остановить**, либо
конфигурация `tt stop -y`, либо `tt stop -y` в терминале.
